# Реалізація одного зрізу Luden (ЛР 2)

Специфікація ЛР1 у `docs/requirements.md` і навчальний wire-контракт `docs/lr2-api.md` — єдині джерела правил. Не змінюй їх, щоб спростити патч. Шляхи `docs/`, `app/`, `tests/` — від кореня репозиторію; `references/` — від теки цього Skill.

## Розподіл відповідальності (docs/architecture.md, адаптація FastAPI)

- `schemas.py` — перевірка вхідних даних;
- `services.py` — бізнес-правила: переходи статусів Bill, фільтрація каталогу, бібліотека, повторна покупка;
- `database.py` — збереження даних (SQLite);
- `routes.py` / `main.py` — перетворення результатів на HTTP-відповіді.

Розміщуй кожну зміну в шарі, якому вона належить.

## Процедура

1. Визнач зріз (A–E) за запитом. Якщо запит охоплює кілька зрізів, запропонуй розділити роботу й почни з одного.
2. Знайди зріз у `references/slices.md` і прочитай лише зазначені там розділи `docs/`.
3. Перелічи перевірки: критерії приймання та сценарії T-xx, яких стосується зміна.
4. Дай план із 3–5 пунктів і дочекайся підтвердження.
5. Внеси мінімальну зміну лише в дозволених для зрізу файлах, разом із тестами для сценаріїв із кроку 3.
6. Перед запуском перевір свій diff: якщо він працює з файлами поза `tmp_path`, з мережею, запускає процеси або видаляє дані — зупинись і дочекайся підтвердження.
7. Запусти перевірки з кореня репозиторію:

```text
python -m pytest -q
python -m ruff check app tests --select E4,E7,E9,F,I
```

Якщо щось падає — виправ код і запусти знову. Після двох невдалих спроб зупинись і опиши ймовірну причину: далі діагностує людина.
8. Наведи фактичний підсумок перевірок і окремо — що не зроблено або потребує рішення людини.

## Заборони

- Не змінюй маршрути, поля й коди відповідей, визначені в `docs/lr2-api.md`.
- Не додавай і не оновлюй залежності; не змінюй налаштування середовища.
- Запускай лише команди перевірки з кроку 7.
- Наявні тести змінюй, лише якщо вони суперечать контракту, і поясни чому; не видаляй перевірки й не пропускай тести, щоб вони пройшли.
- Не додавай функцій поза обсягом ЛР2: Stripe/Firebase, OAuth, ролі понад seeded Admin/User, email, вкладення, видалення проданих товарів, пагінацію, Docker, хмару, повнотекстовий пошук поза `q`+`category`.
- SQL — лише параметризовані запити; тести — лише на тимчасовій базі (`tmp_path`).
- Не стверджуй, що перевірки пройшли, не запустивши їх. Рішення прийняти зміну — за людиною.

## Формат відповіді

Зріз → прочитані розділи docs/ → перевірки → план → diff → підсумок pytest і ruff → що не зроблено.
